# ce-net-proto

The open ce-net capability token: Ed25519-signed, attenuating capability chains that anyone can
verify **offline** with nothing but the token and a root public key.

- Wire-compatible, byte for byte, with `ce-cap` in the `ce` repo (`tests/compat.rs` proves it both ways).
- Dependencies: `serde`, `bincode` 1, `ed25519-dalek` 2, `sha2`, `hex`. No RNG, no VRF, no network.
- Format spec for other languages: [`docs/TOKEN-FORMAT.md`](docs/TOKEN-FORMAT.md);
  golden vectors: [`tests/vectors.json`](tests/vectors.json) (generated by `cargo test --test vectors`,
  regenerate with `CE_NET_PROTO_REGEN=1`); an independent Python verifier written from the spec:
  [`docs/reference/ce_cap_verify.py`](docs/reference/ce_cap_verify.py).

## Quickstart

Use it as a library (Rust 1.85 or newer, edition 2024):

```toml
[dependencies]
ce-net-proto = { git = "https://github.com/ce-net/ce-net-proto" }
```

Or build and try the tools from a clone:

```
git clone https://github.com/ce-net/ce-net-proto
cd ce-net-proto
cargo test --workspace
cargo run --example explain
cargo run --bin ce-cal -- explain examples/raspberry-pi.cal --refs examples/cal.refs.json
```

## CAL, the cell auth language

A small readable text that compiles to v3 capability links and programs and decompiles back;
spec and grammar: [`docs/CAL.md`](docs/CAL.md). Every name in it is a ce-ref pinned by hash, full
node id or key, so a compiled link means the same thing wherever it is read.

```
person:leif grants agent:planner {
  may grant printer3d:print to anyone depth 1
  on node:printer-1
  until 2027-01-22T08:00Z
  via agent:printer-guard
}
```

```
cargo install --path .
ce-cal explain examples/raspberry-pi.cal --refs examples/cal.refs.json
ce-cal compile examples/raspberry-pi.cal --refs examples/cal.refs.json --key leif.key --key planner.key
ce-cal check <token> --refs examples/cal.refs.json --node node:pi-01 --as agent:agent-b --program b94f --content run.py
```

Examples (each with its checked-in `explain` output): [`examples/`](examples). SDKs over one JSON
API: Rust (this crate, `cal` module; `cargo run --example explain`), TypeScript
([`sdk/ts`](sdk/ts), wasm-bindgen) and the C ABI for Python and any C FFI ([`sdk/python`](sdk/python)).

## CLI

```
cargo install --path .
ce-cap-verify <chain-hex|-> --root <pubkey-hex> [--now <unix-secs>] \
    [--revoked <issuer-hex>:<nonce>]... [--action <ability>] [--holder <pubkey-hex>]
```

Exit 0 = valid (prints holder, abilities, resource, expiry), 1 = invalid (prints the reason), 2 = usage.
It runs `verify_chain`: everything a node's `authorize` checks except the node-specific resource
match; `--action` and `--holder` add the leaf checks.

## Tests

`cargo test --workspace` runs the ported ce-cap unit tests, the vector tests and the CLI tests.
The cross-implementation tests against the in-tree `ce-cap` live in [`compat/`](compat), outside the
workspace, because they need the `ce` repo checked out next to this one:
`cargo test --manifest-path compat/Cargo.toml`.
The CAL tests are `src/cal/tests.rs`, `tests/cal_examples.rs` (the examples against their
`explain` text and against the v3 vectors) and `tests/cal_cli.rs`; the SDKs test with
`npm test` in `sdk/ts` (see its README).
